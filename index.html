I will write a paragraph for each methodology of SDLC. There are many of them, but I will suggest a few. My suggestions and reasons are as follows:

a) Waterfall Model: This model is easy to understand and use, where each phase (requirements, design, implementation, Test, Installation, and maintenance is completed sequentially. Its structured nature makes it ideal for projects with clearly defined requirements and minimal expected changes. This linear approach may create a false sense of progress and fails to align with the iterative nature of problem-solving in software development. It can be used when the requirements are well known, also for a new version of existing product.

b) RAD (Rapid Application Development) model: It consists of four phases: Requirements Planning( structured discussions to define business problems), User Description (using automated tools to gather user input), Construction (leveraging productivity tools), and Cutover( involves installation, user testing, and training). RAD’s strengths include reduced cycle time, lower costs, and enhanced customer satisfaction through continuous involvement. It works best for modular systems with well-known requirements, with low technical risks, and incremental functionality delivery.

c) Agile Models: It is a flexible and iterative software development methodology that emphasizes collaboration, adaptability, and customer satisfaction. It focuses on delivering small, incremental updates of a product through short development cycles knowns as iterations. Agile promotes close collaboration between cross-functional teams and stakeholders, making it ideal for dynamic environments and projects with evolving requirements.

Among so many SDLC methodologies, the ones that are in the Agile classification are better. Among Agile SDLC methods, I have also a few suggestions:

a) Scrum: It is a widely-used framework designed to manage and complete complex projects, Work is divided into sprints, a sprint is a short timeframe where developers focus on building important features which will become the part of final product.

b) Extreme Programming (XP): It focuses more on software quality and it is much strict than scrum. Here, code is frequently tested and shown to customer to detect any issue at the early stage or to recieve feedback/suggestion from the customer to shape the product as per the requirement. It promotes frequent releases in short development cycles to resduce the risk of building unnecessary features.

c) Kanban: It is a visual workflow management method where tasks are displayed on a Kanban board, moving through different phases like “To Do,” “In Progress,” and “Done.” This way each state of a task is visible to the whole team, which helps in better resource allocation and a streamlined workflow.

d) Crystal clear: it is a light-weight methodology that does not require much documentation, and it focuses on simplicity, face-to-face communication, and frequent delivery of working software. Regular reflection workshops help the team identify and address process improvements. However, it lacks pre-defined scope which can pause the overall development process

I Have used CSS in this webpage and there are three ways to include CSS in a webpage as follows.

a) Inline CSS: It is applied directly to an HTML element using the style attribute.

b) External CSS: A separate CSS file is linked to the HTML document using the link tag in the head section.

c) Internal CSS: A CSS is placed within the style tag in the html file.

The reasons CSS is used in a webpage are:

1. It allows developers to define the design of the website such as colors, fonts, layouts.

2. With CSS, webpages can be responsive and visually appealing by using features like animations, transitions and media queries.

3. By using a external CSS file, it gets easier to maintain, develop and manage the code.

We also use Javascript in webpage development, the main reasons are as follows:

a) Javascript is used to program the behavior of web pages such as interactive features like form validation, dropdowns, sliders, and dynamic updates, enhancing user engagement.

b) It can be used both on the client side (in the browser) and server side (via Node.js), making it a powerful tool for building full-stack web applications.

c) JavaScript works across all major browsers and platforms, ensuring consistent functionality and a seamless user experience.

d) By enabling animations, event handling, and responsive behaviors, JavaScript creates a smooth, dynamic, and engaging interface for users.
